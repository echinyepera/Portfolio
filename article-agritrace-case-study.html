AgriTrace: Fighting Counterfeit Agricultural Inputs with USSD Technology

May 10, 2025 8 min read Case Study / AgriTech

Every farming season in Zimbabwe, counterfeit agricultural inputs destroy livelihoods. Fake seeds packaged as trusted brands, fertilizers that are actually sand and ash — farmers only discover the truth when crops fail months after planting. By then, it's too late.

This case study documents my final year project, AgriTrace — a mobile-based agricultural input verification system that allows farmers to authenticate products instantly using any mobile phone, even basic feature phones with no internet connection.

📌 Project Status: Completed as a final year project. Fully functional prototype developed. Code kept private for intellectual property considerations.

The Problem

Zimbabwe's agricultural sector supports over 70% of the population. Yet counterfeit agricultural inputs are rampant:

From interviews with farmers, manufacturers, and law enforcement, I identified four critical gaps:

  • No unified platform: Each manufacturer has its own verification system (if any)
  • Reactive detection: Farmers discover counterfeits only after crop failure — months later
  • Inaccessible: Most systems require smartphones and internet
  • No intelligence: Manufacturers have zero visibility into where their products are sold

The Solution Overview

AgriTrace is a USSD-based verification system that works on any mobile phone. Farmers dial a shortcode, enter a 12-digit product code, and receive an instant verification result.

Key Features

1. USSD Verification (Farmer-Facing)

  • Works on ANY mobile phone — feature phones, smartphones, all networks
  • No internet required
  • Simple numeric menu (no literacy required)
  • Instant verification with product details (brand, type, expiry)
  • Automatic GPS location capture (for hotspot mapping)

2. Manufacturer Dashboard

  • Real-time interactive map showing verification locations across Zimbabwe
  • Live statistics (total verifications, genuine/fake counts, active alerts)
  • Verification history with filters (date, product, region)
  • Product and batch management
  • Bulk code generation and download

3. Anomaly Detection & Alerts

  • System compares verification location against expected distribution region
  • Automatic alerts when products are verified outside intended regions
  • Severity levels: HIGH (counterfeit suspect) vs MEDIUM (diversion)
  • Email + SMS notifications to manufacturers

4. Evidence Package Generation

  • Downloadable PDF evidence with GPS coordinates and timestamps
  • SHA-256 hash for integrity verification
  • Compliant with Zimbabwe's Electronic Transactions and Cyber Security Act
  • Designed for law enforcement prosecution

Database Design

The database was normalized to 3NF with eight core tables:

  • manufacturer – Company details and authentication
  • product – Product catalog (seeds, fertilizers, chemicals)
  • batch – Manufacturing batches with expiry dates
  • region – Geographic distribution areas (with PostGIS polygons)
  • product_code – 12-digit unique verification codes
  • verification – Every verification attempt with GPS location
  • alert – Anomaly detection records
  • evidence_package – Generated evidence for law enforcement

Key Challenges & Solutions

⚠️ Challenge 1: Installing PostGIS on Windows

Multiple PostgreSQL versions conflicted. PostGIS extension wouldn't enable. Solution: Clean install using PostgreSQL+PostGIS bundle and proper PATH configuration. Lesson learned: Linux deployment would have been easier.

✅ Solution 1: Development with SQLite → PostgreSQL at deployment

Built the system with SQLite for rapid development, then migrated to PostgreSQL+PostGIS for production. This saved weeks of debugging.

⚠️ Challenge 2: USSD Session State Management

USSD is stateless — each request is independent. Maintaining user progress through multi-step verification required careful session handling and state tracking in the database.

✅ Solution 2: Session-based State Machine

Implemented a state machine that tracks where the user is in the USSD flow (MAIN_MENU, AWAIT_CODE, AFTER_VERIFY) and stores progress in Redis cache.

⚠️ Challenge 3: Geospatial Anomaly Detection

Detecting when a product is verified outside its expected region required efficient point-in-polygon queries across thousands of verifications.

✅ Solution 3: PostGIS Spatial Functions

Used PostGIS ST_Within and ST_Distance functions to check if verification points fall within expected region polygons. Alerts trigger when distance exceeds thresholds.

Lessons Learned

Technical Lessons

  • USSD is powerful but limited: Session timeouts, character limits, and lack of back buttons require careful UX design
  • PostGIS on Windows is painful: For geospatial projects, develop on Linux or use cloud databases
  • Normalize early: A clean database schema prevents headaches later
  • Test on real devices: USSD simulators don't catch all edge cases

Project Management Lessons

  • Requirements evolve: Manufacturers didn't know they needed anomaly detection until they saw the prototype
  • User feedback is gold: Farmers wanted shorter codes, so I redesigned the code format
  • Document as you build: Future you will thank past you
💡 Biggest Insight: Technology is only half the solution. The real value comes from understanding the business problem deeply and designing for the user's constraints (feature phones, low literacy, no internet).

Future Enhancements

If this project were to move to production, I would add:

  • Mobile app: For farmers with smartphones (QR code scanning, offline mode)
  • Predictive analytics: ML models to forecast counterfeit hotspots
  • Blockchain integration: Immutable verification records
  • Multi-language support: Shona and Ndebele USSD menus
  • SMS fallback: When USSD networks are congested

Conclusion

AgriTrace demonstrates how appropriate technology (USSD) can solve a critical real-world problem. By focusing on accessibility (any phone, no internet), real-time intelligence (GPS tracking, anomaly alerts), and practical outcomes (evidence for prosecution), the system addresses the counterfeit crisis from multiple angles.

This project reinforced my belief that the best technologists are those who deeply understand the problem and design for the user's reality — not their own.
